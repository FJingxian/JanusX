# JanusX v2.0.1 Release Notes

Compared with v2.0.0, v2.0.1 completes end-to-end PGEN workflows, adds PGEN output to `gformat`, simplifies the GWAS model surface, and fixes cross-platform GS/GWAS issues.

## Highlights

- **Native PGEN GWAS:** `gwas -pfile` now runs LM, LMM, LMM2, and FvLMM through native Rust scans. LM uses a dedicated PGEN scanner with the same QC, mean-imputation, QR projection, and `chisq = n·ln(1+t²/df)` semantics as BED LM.
- **PGEN output in `gformat`:** `-fmt` now uses `bfile` for PLINK BED and `pfile` for PGEN/PVAR/PSAM. The default is `bfile`. PGEN output uses the BED-compatible hard-call storage mode and round-trips to BED byte-for-byte.
- **Broader PGEN coverage:** `gstats`, PCA, `postgwas`, SparseLMM, and GARFIELD accept `-pfile`, and `gformat` handles PGEN as both input and output.
- **GWAS surface cleanup:** the `-lm2` interaction model has been removed. Mixed models no longer downgrade to LM automatically when a null-model LRT is not significant; choose `-lm` explicitly when needed. `-lmm2` remains supported.
- **Performance:** LMM/LMM2 reuse REML and eigen workspaces across markers; GARFIELD window scans stream QC, LD selection, and output. On the 1.7M-SNP CUBIC benchmark, PGEN LM improved from 2.01× slower than BED to 0.88× (22.81 s vs 25.86 s), while LMM/LMM2 stayed at BED parity.
- **Genomic selection correctness:** `-strict-cv` now defaults to true and `-pcd` fits PCA on the training partition only, reducing validation leakage.
- **Bayesian GS stability:** BayesA/B/C/R cap BLAS/OpenMP at one thread before NumPy import while keeping Rayon at `-t`, avoiding oversubscription and login-node CPU-guard kills.

## Correctness and validation

- PGEN and BED GWAS outputs agree within output precision after accounting for REF/ALT orientation: `beta` flips sign when alleles are reversed, while `se`, `chisq`, and `pwald` match.
- CUBIC 1.7M: LM significance sets at 1e-8/5e-8/1e-5/1e-4 are identical and the top-10k intersection is 10,000/10,000; LMM/LMM2 agree across all tested significance thresholds.
- PLINK 2 external control: PGEN ALT frequencies and per-sample dosages match BED exactly; JanusX PGEN→BED conversion reproduces the original BED payload byte-for-byte.
- Fixed FarmCPU scan paths and repaired the `ggval` smoke workflow.
- Windows: configured UTF-8 stdio before subcommand dispatch so `postgs` no longer crashes on legacy GBK console code pages.

## Compatibility changes

- `-lm2` / LM2 is removed; use `-lmm2` for the mixed interaction model.
- `gformat -fmt plink` is replaced by `gformat -fmt bfile`. `gmerge -fmt plink` is unchanged.
- LMM/LMM2/FvLMM no longer automatically switch to LM after a non-significant null LRT.
- GS `-strict-cv` defaults to true; `-pcd` projects test samples from a training-only PCA.
- GARFIELD without `-k` defaults to LM/OLS residuals; pass `-k` when exact GRM-eig/REML residuals are required.

## Builds and platforms

- Wheel matrix: Linux x86_64/aarch64, macOS arm64, Windows x86_64/arm64, plus source distribution.
- macOS arm64: `cargo test --locked --lib` passed 977 tests (7 ignored); Python tests passed; `ggval --mode smoke` passed.
- Linux x86_64: PGEN BED/PGEN roundtrip, PGEN LM/LMM/LMM2, `-fmt` behavior, and `ggval --mode smoke` passed on the JXFU compute node.
- Windows x86_64: CI-style wheel build/install, BED↔PGEN roundtrip, PGEN LM/LMM/LMM2, and `ggval --mode smoke` passed.

The `2.0.1.dev3` TestPyPI build was produced before the final gformat and Windows fixes. Use `2.0.1` for the complete feature set.

## Install

```bash
python -m pip install janusx==2.0.1
```

# JanusX v2.0.1 发布说明

相较于 v2.0.0，v2.0.1 补齐了 PGEN 端到端工作流，为 `gformat` 增加 PGEN 输出，收敛 GWAS 模型接口，并修复跨平台 GS/GWAS 问题。

## 主要更新

- **GWAS 原生 PGEN：** `gwas -pfile` 的 LM、LMM、LMM2、FvLMM 均使用原生 Rust 扫描。LM 新增专用 PGEN 扫描器，QC、均值填补、QR 投影和 `chisq = n·ln(1+t²/df)` 语义与 BED 一致。
- **`gformat` 支持 PGEN 输出：** `-fmt` 改为 `bfile`（BED）和 `pfile`（PGEN/PVAR/PSAM），默认 `bfile`。PGEN 使用 BED-compatible hard-call 模式，PGEN→BED 可逐字节还原。
- **PGEN 覆盖扩展：** `gstats`、PCA、`postgwas`、SparseLMM、GARFIELD 均支持 `-pfile`，`gformat` 同时支持 PGEN 输入和输出。
- **GWAS 模型清理：** 移除 `-lm2` 交互模型；混合模型不再因 null-model LRT 不显著而自动退化为 LM，如需 LM 请显式使用 `-lm`。`-lmm2` 保留。
- **性能：** LMM/LMM2 跨标记复用 REML 与特征分解工作区；GARFIELD 窗口扫描对 QC、LD 筛选和输出进行流式处理。CUBIC 1.7M 基准中，PGEN LM 从比 BED 慢 2.01× 改善为 0.88×（22.81 s vs 25.86 s），LMM/LMM2 与 BED 基本持平。
- **基因组选择正确性：** `-strict-cv` 默认开启；`-pcd` 只在训练集拟合 PCA，降低验证泄漏。
- **BayesA 稳定性：** BayesA/B/C/R 在导入 NumPy 前将 BLAS/OpenMP 限制为 1，Rayon 仍使用 `-t`，避免线程过度订阅和登录节点 CPU 守卫生效。

## 正确性与验证

- PGEN 与 BED 的 GWAS 结果在输出精度内一致：等位基因方向相反时 `beta` 符号翻转，`se/chisq/pwald` 不变。
- CUBIC 1.7M：LM 在 1e-8/5e-8/1e-5/1e-4 的显著性集合完全一致，Top 10k 交集 10,000/10,000；LMM/LMM2 在所有测试阈值上一致。
- PLINK 2 外部对照：PGEN 的 ALT 频率和逐样本 dosage 与 BED 完全一致；JanusX PGEN→BED 转换结果与原始 BED 字节级一致。
- 修复 FarmCPU 扫描路径和 `ggval` smoke 流程。
- Windows：子命令分发前统一将 stdio 配置为 UTF-8，`postgs` 不再因 GBK 控制台编码崩溃。

## 兼容性变更

- 移除 `-lm2`/LM2；混合交互模型请使用 `-lmm2`。
- `gformat -fmt plink` 改为 `gformat -fmt bfile`；`gmerge -fmt plink` 保持不变。
- LMM/LMM2/FvLMM 不再在 null LRT 不显著时自动切换到 LM。
- GS `-strict-cv` 默认开启；`-pcd` 使用仅训练集的 PCA 投影。
- GARFIELD 未提供 `-k` 时默认使用 LM/OLS 残差；需要 exact GRM-eig/REML 时请显式传 `-k`。

## 构建与平台

- Wheel 矩阵：Linux x86_64/aarch64、macOS arm64、Windows x86_64/arm64，以及源码包。
- macOS arm64：`cargo test --locked --lib` 通过 977 项测试（7 项忽略）；Python 测试通过；`ggval --mode smoke` 通过。
- Linux x86_64：PGEN/BED 双向转换、PGEN LM/LMM/LMM2、`-fmt` 行为、`ggval --mode smoke` 在 JXFU 计算节点通过。
- Windows x86_64：CI 方式构建并安装 wheel，BED↔PGEN 双向转换、PGEN LM/LMM/LMM2、`ggval --mode smoke` 通过。

`2.0.1.dev3` TestPyPI 构建早于最终的 gformat 和 Windows 修复；完整功能请使用 `2.0.1`。
